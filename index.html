مقدمة في البرمجة كائنية التوجه (OOP)

What is OOP • Programming Paradigms • Objects & Classes

📖 الشرح

ما هي البرمجة كائنية التوجه؟

OOP هي أسلوب برمجة بيتعامل مع البرنامج على أساس إنه مجموعة من Objects (كائنات). كل object بيتجمع فيه:

  • 📦 Data (بيانات) — زي اسم الطالب، رقمه، الـ GPA
  • ⚙️ Operations/Methods (عمليات) — زي تعديل الـ GPA، طباعة البيانات

الفرق بين البرمجة الإجرائية (Procedural) و OOP

  • Procedural: بتكتب قائمة تعليمات خطوة بخطوة من فوق لتحت (top-down approach)
  • OOP: بتفكر في المشكلة على أنها كائنات بتتفاعل مع بعض

Class vs Object

  • 🏗️ Class: المخطط التصميمي (Blueprint) — زي تصميم الشقة
  • 🏠 Object: النسخة الفعلية (Instance) — زي الشقة المبنية فعلاً
  • ممكن تعمل كذا object من نفس الـ class
Java - مثال بسيط
// Class = المخطط (Blueprint)
public class Student {
    String name;
    int id;
    double gpa;
}

// Objects = نسخ حقيقية من الـ Class
Student s1 = new Student(); // Student 1
Student s2 = new Student(); // Student 2
✍️ أسئلة نظرية
  • 1ما المقصود بـ Programming Paradigm؟ وما الفرق بين البرمجة الإجرائية وبرمجة OOP؟
    ✅ Programming Paradigm = أسلوب تفكير في كتابة البرامج.
    • Procedural: تكتب تعليمات خطوة بخطوة من فوق لتحت (top-down) — البيانات والوظائف منفصلة.
    • OOP: البرنامج مجموعة objects تحمل بيانات وعمليات وتتفاعل مع بعض — الكود أكثر تنظيماً وإعادة استخدام.
  • 2ما هو الـ Object؟ اذكر مثالاً من الحياة اليومية مع تحديد البيانات والعمليات.
    ✅ Object = وحدة في البرنامج تجمع بيانات وعمليات مع بعض.
    مثال — سيارة:
    • البيانات (Data): اللون، الموديل، السنة، السرعة الحالية
    • العمليات (Operations): تشغيل()، وقف()، تسريع()، كبح()
  • 3ما الفرق بين الـ Class والـ Object؟ وما معنى "Instance of a class"؟
    ✅ Class = المخطط التصميمي (Blueprint) — بيحدد شكل وسلوك الـ class بس ما بينفذش بنفسه.
    Object = النسخة الحقيقية (Instance) المُنشأة من الـ class.
    "Instance of a class" = يعني object تم إنشاؤه من class معين. مثال: s1 = new Student() → s1 هو instance من Student.
  • 4لو بتصمم برنامج لإدارة مكتبة، اذكر 4 objects مختلفة مع بياناتها وعملياتها.
    ✅ 1. Book: بيانات: title, author, isbn, isAvailable — عمليات: borrow(), returnBook(), display()
    2. Member: بيانات: name, id, phone — عمليات: register(), borrowBook(), returnBook()
    3. Librarian: بيانات: name, employeeId — عمليات: addBook(), removeBook(), searchBook()
    4. Library: بيانات: name, address, openingHours — عمليات: searchByTitle(), listAvailableBooks()

كتابة الـ Classes — Access Modifiers & Encapsulation

Fields • Methods • Getters & Setters • Data Hiding

📖 الشرح

Access Modifiers

  • 🔓 public: يُوصله أي كود من أي مكان
  • 🔒 private: يُوصله بس الـ methods جوه نفس الـ class
  • 🔐 protected: يُوصله الـ subclasses وأي class في نفس الـ package

Data Hiding (Encapsulation)

المبدأ: اجعل الـ fields كلها private وفرّ public methods للوصول إليها

  • 🛡️ Getter (Accessor): يجيب قيمة الـ field — يبدأ بـ get
  • ✏️ Setter (Mutator): يغير قيمة الـ field — يبدأ بـ set
Java - Rectangle Class
public class Rectangle {
    private double length; // private — لا يُوصله من الخارج
    private double width;

    // Setter
    public void setLength(double len) { length = len; }
    public void setWidth(double w)   { width = w;   }

    // Getter
    public double getLength() { return length; }
    public double getWidth()  { return width;  }

    public double getArea() { return length * width; }
}

// الاستخدام
Rectangle box = new Rectangle();
box.setLength(10.0);
box.setWidth(5.0);
System.out.println("Area: " + box.getArea()); // 50.0
✍️ أسئلة نظرية
  • 1ما الفرق بين public و private كـ access modifiers؟ ولماذا نفضل جعل الـ fields خاصة (private)؟
    ✅ public: يوصله أي كود من أي مكان في البرنامج.
    private: يوصله بس methods جوه نفس الـ class بالظبط.
    نفضل private لأن: (1) نحمي البيانات من التعديل الخاطئ، (2) نتحكم في آلية الوصول عبر getters/setters، (3) نسهل التعديل المستقبلي بدون تأثير على باقي الكود.
  • 2ما المقصود بـ Data Hiding؟ ولماذا هو مهم في برمجة OOP؟
    ✅ Data Hiding = إخفاء التفاصيل الداخلية للـ class عن باقي البرنامج بجعل الـ fields كلها private وتوفير public methods للوصول إليها.
    أهميته: (1) يمنع التعديل الخاطئ للبيانات، (2) يسمح بالتحقق من صحة القيم في الـ setters، (3) يجعل الكود أكثر أماناً وصيانةً.
  • 3ما الفرق بين الـ Getter والـ Setter؟ أعطِ مثالاً لكل منهما.
    ✅ Getter (Accessor): method تبدأ بـ get وترجع قيمة الـ private field — لا تعدلها.
    مثال: public double getBalance() { return balance; }
    Setter (Mutator): method تبدأ بـ set وتعدل قيمة الـ private field — ممكن تضيف تحقق من صحة القيمة.
    مثال: public void setBalance(double b) { if(b >= 0) balance = b; }
  • 4ما هي الـ Instance Fields والـ Instance Methods؟ لماذا تحتاج لإنشاء Object لاستخدامها؟
    ✅ Instance Fields: متغيرات معرفة داخل الـ class بدون static — كل object عنده نسخته الخاصة منها (مثال: name, age).
    Instance Methods: methods بتشتغل على بيانات الـ object وبتوصل لـ instance fields.
    لازم تعمل object لأن كل object له بياناته المختلفة — ما فيش "بيانات مشتركة" مثل static.

🔹 اكتب class اسمه BankAccount يحتوي على: balance (double), accountName (String) — جميعها private، مع الـ Getters والـ Setters المناسبة وـ method تسمى deposit تضيف مبلغ للرصيد وأخرى withdraw تطرح منه.
Java - Solution
public class BankAccount {
    private double balance;
    private String accountName;

    public void setBalance(double b)      { balance = b; }
    public void setAccountName(String n) { accountName = n; }

    public double getBalance()     { return balance; }
    public String getAccountName() { return accountName; }

    public void deposit(double amount) {
        if (amount > 0) balance += amount;
    }

    public void withdraw(double amount) {
        if (amount > 0 && amount <= balance)
            balance -= amount;
        else
            System.out.println("Insufficient funds!");
    }
}

Constructors & Static Members & Copy Objects

Constructors • Overloading • Static Fields & Methods • Copy Constructor

📖 الشرح

الـ Constructor (المُنشئ)

  • Method بيتنادي تلقائياً لما بتعمل Object
  • نفس اسم الـ Class، ومعندوش return type
  • لو ما كتبتش constructor، Java بتوفر default constructor تلقائياً

Method Overloading

نفس اسم الـ method بس بـ parameters مختلفة — Java بتعرف تنادي أنهي واحدة حسب الـ arguments

Static Members

  • الـ static fields والـ static methods مش بتتبع لـ object بعينه — بتتبع للـ class نفسه
  • بتستخدمها باسم الـ class: Math.sqrt(25)
  • الـ static methods مش قادرة توصل للـ instance fields
Java - Constructors & Overloading
public class Rectangle {
    private double length, width;

    // No-arg constructor
    public Rectangle() {
        length = 1.0;
        width  = 1.0;
    }

    // Parameterized constructor
    public Rectangle(double len, double w) {
        length = len;
        width  = w;
    }

    // Copy constructor
    public Rectangle(Rectangle other) {
        length = other.length;
        width  = other.width;
    }

    public double getArea() { return length * width; }
}

// الاستخدام
Rectangle r1 = new Rectangle();        // 1x1
Rectangle r2 = new Rectangle(5.0, 10.0); // 5x10
Rectangle r3 = new Rectangle(r2);       // نسخة من r2
Java - Static Members
public class Counter {
    private static int count = 0; // مشترك بين كل الـ objects

    public Counter() { count++; }

    public static int getCount() { return count; }
}

Counter c1 = new Counter();
Counter c2 = new Counter();
System.out.println(Counter.getCount()); // 2
✍️ أسئلة نظرية
  • 1ما هو الـ Constructor؟ اذكر 4 خصائص تميزه عن الـ methods العادية.
    ✅ Constructor = method خاصة بتتنادى تلقائياً عند إنشاء object.
    4 خصائص تميزه:
    (1) نفس اسم الـ class بالظبط
    (2) لا يوجد له return type (حتى void مش موجود)
    (3) بيتنادى تلقائياً بالكلمة new
    (4) ممكن يكون متعدد (Overloading) بـ parameters مختلفة
  • 2ما هو الـ Default Constructor؟ متى تتوفره Java تلقائياً ومتى لا؟
    ✅ Default Constructor = no-arg constructor بدون parameters بيضع قيم افتراضية (0, null, false).
    • Java بتوفره تلقائياً: لما ما تكتبش أي constructor في الـ class.
    • Java لا تتوفره: لو كتبت constructor واحد على الأقل — حينها لازم تكتب الـ no-arg بنفسك لو محتاجه.
  • 3ما المقصود بـ Method Overloading؟ وما الفرق بينه وبين Method Overriding؟
    ✅ Method Overloading: نفس الاسم في نفس الـ class لكن بـ parameters مختلفة (عدد أو نوع) — Java تعرف تنادي أنهي نسخة حسب الـ arguments. بيتحل في compile time.
    Method Overriding: الـ subclass تعيد كتابة method من الـ superclass بنفس الـ signature تماماً. بيتحل في runtime.
  • 4ما الفرق بين الـ Static field والـ Instance field؟ أعطِ مثالاً توضيحياً.
    ✅ Static field: مشترك بين كل الـ objects — نسخة واحدة في الذاكرة لكل الـ class. يُنادى باسم الـ class: Counter.count
    Instance field: كل object عنده نسخته الخاصة — قيمه مختلفة لكل object. يُنادى باسم الـ object: student.name
    مثال: static int count (عداد الطلاب الكلي) مقابل String name (اسم كل طالب).
  • 5ما الفرق بين الـ Reference copy والـ Deep copy؟ ولماذا نستخدم Copy Constructor؟
    ✅ Reference copy (Rectangle r2 = r1): الاتنين بيشيروا لنفس الـ object في الذاكرة — تعديل r2 يأثر على r1 وبالعكس!
    Deep copy (Rectangle r2 = new Rectangle(r1)): نسخة مستقلة جديدة تماماً في الذاكرة — تعديل r2 لا يأثر على r1.
    نستخدم Copy Constructor عشان نعمل نسخة مستقلة آمنة من الـ object.

public class Student {
    private String name;
    private int    id;
    private double gpa;
    private static int count = 0;

    // No-arg constructor
    public Student() {
        name = "Unknown";
        id   = 0;
        gpa  = 0.0;
        count++;
    }

    // Parameterized constructor
    public Student(String n, int i, double g) {
        name = n; id = i; gpa = g;
        count++;

    public Student(Student other) {
        name = other.name;
        id   = other.id;
        gpa  = other.gpa;
        count++;
    }

    public static int getCount() { return count; }

    public void print() {
        System.out.println(name + " | ID: " + id + " | GPA: " + gpa);
    }
}

الوراثة (Inheritance)

extends • super • Method Overriding • protected • final

📖 الشرح

ما هي الوراثة؟

الـ Inheritance بتخلي الـ Subclass ترث الـ fields والـ methods من الـ Superclass، وتضيف عليها خصائص جديدة.

  • علاقة "is a": الـ Employee "is a" Person
  • الـ Superclass = Parent Class = Base Class
  • الـ Subclass = Child Class = Derived Class
  • الكلمة المفتاحية: extends

Method Overriding

الـ Subclass تعيد كتابة method من الـ Superclass بنفس الـ signature لكن بتنفيذ مختلف.

  • يُستخدم annotation: @Override
  • للوصول لنسخة الـ Superclass: super.methodName()
  • لمنع الـ Override: استخدم final
Java - Inheritance Example
// Superclass
public class Person {
    protected String name;
    protected int    age;

    public Person(String n, int a) { name = n; age = a; }

    public void display() {
        System.out.println("Name: " + name + ", Age: " + age);
    }
}

// Subclass
public class Employee extends Person {
    private double salary;

    public Employee(String n, int a, double s) {
        super(n, a); // نُنادي Constructor الـ Superclass
        salary = s;
    }

    // Override display method
    @Override
    public void display() {
        super.display(); // نُنادي نسخة الـ Superclass
        System.out.println("Salary: " + salary);
    }
}

// الاستخدام
Employee emp = new Employee("Ahmed", 30, 5000.0);
emp.display();
✍️ أسئلة نظرية
  • 1ما المقصود بعلاقة "is a" في الوراثة؟ أعطِ 3 أمثلة.
    ✅ علاقة "is a" تعني أن الـ subclass هو نوع من الـ superclass — يعني الـ subclass يرث كل خصائص وسلوك الـ superclass.
    أمثلة:
    • Employee "is a" Person → الموظف هو شخص
    • Dog "is a" Animal → الكلب هو حيوان
    • Circle "is a" Shape → الدائرة هي شكل هندسي
  • 2ما دور الكلمة المفتاحية super في الوراثة؟ اذكر استخدامين لها.
    ✅ super = كلمة مفتاحية بتُشير للـ superclass.
    (1) super(args): ينادي constructor الـ superclass — لازم تكون أول سطر في الـ subclass constructor. مثال: super("Ahmed", 30);
    (2) super.methodName(): ينادي نسخة الـ method من الـ superclass من جوه الـ subclass. مثال: super.display();
  • 3ما الفرق بين Method Overriding وMethod Overloading؟
    ✅ Method Overriding: الـ subclass تعيد كتابة method من الـ superclass بنفس الاسم ونفس الـ parameters تماماً (@Override). بيتحقق في Runtime (Dynamic Binding).
    Method Overloading: نفس الـ class يعرف methods بنفس الاسم لكن parameters مختلفة في العدد أو النوع. بيتحقق في Compile Time (Static Binding).
  • 4ما الفرق بين private وprotected من حيث الوصول في الوراثة؟
    ✅ private: يوصله بس نفس الـ class اللي عرّفه — الـ subclass لا تستطيع الوصول المباشر، لازم تستخدم public getters/setters.
    protected: يوصله نفس الـ class + كل الـ subclasses + كل الـ classes في نفس الـ package.
    في الوراثة، الـ protected أنسب لأنه بيوفر الوصول للـ subclasses مع حماية من الكود الخارجي.
  • 5ما تأثير الكلمة المفتاحية final على الـ method؟
    ✅ الـ final method = method لا يمكن للـ subclasses عمل override لها.
    مثال: public final void display() { ... } → لو حاولت تعمل override لها في الـ subclass يطلع Compiler Error.
    تُستخدم لما تريد ضمان أن سلوك معين لا يتغير في أي subclass.

Abstract Classes & Interfaces & Polymorphism

abstract • interface • implements • Polymorphism

📖 الشرح

Abstract Class

  • لا يمكن إنشاء Object منها مباشرةً
  • بتكون Superclass لـ classes أخرى
  • ممكن تحتوي على abstract methods (بدون body) وعادية
  • الـ Subclass لازم تُنفذ كل الـ abstract methods

Interface

  • زي abstract class لكن كل methods فيها abstract
  • الـ fields فيها تلقائياً public static final
  • الـ class ممكن تُنفذ (implements) أكتر من interface
  • الكلمة المفتاحية: implements
Java - Abstract Class
public abstract class Animal {
    protected String name;

    public Animal(String n) { name = n; }

    // Abstract method — لازم يتنفذ في الـ subclass
    public abstract void makeSound();

    // عادي method
    public void display() {
        System.out.println("Animal: " + name);
    }
}

public class Dog extends Animal {
    public Dog(String n) { super(n); }

    @Override
    public void makeSound() { System.out.println("Woof!"); }
}

public class Cat extends Animal {
    public Cat(String n) { super(n); }

    @Override
    public void makeSound() { System.out.println("Meow!"); }
}
Java - Interface & Multiple Implementation
public interface Printable {
    void print();
}

public interface Saveable {
    void save();
}

// تنفيذ أكتر من interface
public class Document implements Printable, Saveable {
    private String content;

    @Override
    public void print() { System.out.println("Printing: " + content); }

    @Override
    public void save()  { System.out.println("Saving: " + content); }
}
✍️ أسئلة نظرية
  • 1ما المقصود بـ Abstract Class؟ ولماذا لا يمكن إنشاء Object منها مباشرةً؟
    ✅ Abstract Class = class معرّفة بكلمة abstract — تحتوي abstract methods (بدون body) لازم الـ subclasses تنفذها.
    لا يمكن إنشاء object منها مباشرةً لأنها غير مكتملة — فيها methods بدون تنفيذ. هي بس template للـ subclasses. لو حاولت: Animal a = new Animal(); → Compiler Error.
  • 2ما الفرق بين الـ Abstract Class والـ Interface؟ متى تستخدم كل منهما؟
    ✅ Abstract Class: ممكن تحتوي methods عادية وabstract، عندها constructors وinstance fields، الـ class يرثها بـ extends واحدة بس.
    استخدمها: لما يكون فيه كود مشترك بين الـ subclasses.
    Interface: كل methods abstract، الـ fields تلقائياً public static final، الـ class ينفذها بـ implements وممكن أكتر من واحدة.
    استخدمها: لما تريد تحديد عقد (contract) للسلوك بدون تنفيذ مشترك.
  • 3لماذا تسمح Java بتنفيذ أكتر من Interface ولكن لا تسمح بالوراثة من أكتر من class؟
    ✅ الوراثة من أكتر من class بتسبب Diamond Problem: لو Class A وClass B عندهم نفس الـ method، والـ Class C يرث الاتنين — Java مش هتعرف تنفذ نسخة أنهي class!
    الـ Interface بيحل المشكلة لأنه ما عندوش تنفيذ — بس signature. لما تنفذ أكتر من interface، الـ class نفسه هو اللي بيكتب التنفيذ فما فيش تعارض.
  • 4ما هو Polymorphism؟ وكيف يتحقق في Java؟ أعطِ مثالاً.
    ✅ Polymorphism = "أشكال متعددة" — نفس الـ reference ينفذ سلوك مختلف حسب نوع الـ object الفعلي في runtime.
    يتحقق عبر: Method Overriding + Superclass reference pointing to Subclass object.
    مثال:
    Animal a1 = new Dog(); → a1.makeSound(); // Woof!
    Animal a2 = new Cat(); → a2.makeSound(); // Meow!
    نفس النوع Animal، لكن سلوك مختلف حسب الـ object.
  • 5ما المقصود بـ Polymorphism؟ ولماذا مهم؟
    ✅ Polymorphism يعني نفس الـ method يتصرف بأكثر من شكل. مهم لأنه يسمح بإعادة استخدام الكود وتقليل التكرار.
  • 6متى نستخدم Interface بدل Abstract Class؟
    ✅ نستخدم Interface لما نحتاج multiple inheritance أو define behavior فقط بدون implementation.

public static void main(String[] args) {

// ══════════════════════════════════
// 3. ABSTRACT CLASS - الشخص (Base)
// ══════════════════════════════════
public abstract class Person {
    private String name;
    private int    age;
    private static int personCount = 0; // Static — مشترك

    // No-arg constructor
    public Person() {
        name = "Unknown";
        age  = 0;
        personCount++;
    }

    // Parameterized constructor
    public Person(String name, int age) {
        this.name = name;
        this.age  = age;
        personCount++;
    }

    // Copy constructor
    public Person(Person other) {
        this.name = other.name;
        this.age  = other.age;
        personCount++;
    }

    // Getters & Setters
    public String getName() { return name; }
    public int    getAge()  { return age; }
    public void   setName(String n) { name = n; }
    public void   setAge(int a) {
        if (a >= 0 && a <= 120) age = a;
        else throw new IllegalArgumentException("Invalid age!");
    }

    public static int getPersonCount() { return personCount; }

    // Abstract method — لازم ينفذها الـ subclass

public class Employee extends Person implements Payable, Reviewable {
    private int        employeeId;
    private double     basicSalary;
    private Department dept;
    private double     performanceRating;

    public Employee(String name, int age, int id,
                    double salary, Department dept) {
        super(name, age);  // نُنادي Person constructor
        this.employeeId  = id;
        this.basicSalary = salary;
        this.dept        = dept;
        this.performanceRating = 3.0; // default
    }

    // Implement Payable interface
    @Override
    public double calculatePay() {
        return basicSalary + (basicSalary * 0.1); // أساسي + 10% علاوة
    }

    @Override
    public void printPaySlip() {
        System.out.println("==============================");
        System.out.println("  PAY SLIP - " + getName());
        System.out.println("  ID: "       + employeeId);
        System.out.println("  Dept: "     + dept);
        System.out.println("  Net Pay: " + calculatePay());
        System.out.println("==============================");
    }

    // Implement Reviewable interface
    @Override
    public void performanceReview(double rating) {
        if (rating < 1.0 || rating > 5.0)
            throw new IllegalArgumentException("Rating must be 1.0–5.0");
        this.performanceRating = rating;
        System.out.println(getName() + " rated: " + rating);
    }

    // Override abstract method from Person
    @Override
    public void displayInfo() {
        System.out.println("Employee | Name: " + getName() +
                           " | Age: " + getAge() +
                           " | Dept: " + dept +
                           " | Rating: " + performanceRating);
    }

    public double getBasicSalary() { return basicSalary; }
}

public class Manager extends Employee {
    private double bonus;
    private ArrayList<Employee> team;

    public Manager(String name, int age, int id,
                   double salary, Department dept, double bonus) {
        super(name, age, id, salary, dept);
        this.bonus = bonus;
        this.team  = new ArrayList<>();
    }

    // Override calculatePay — يضيف الـ bonus
    @Override
    public double calculatePay() {
        return super.calculatePay() + bonus;
    }

    public void addToTeam(Employee emp) {
        team.add(emp);
        System.out.println(emp.getName() + " added to " + getName() + "'s team");
    }

    public void displayTeam() {
        System.out.println("\n--- Team of " + getName() + " ---");
        for (Employee e : team) e.displayInfo();
    }

    @Override
    public void displayInfo() {
        System.out.println("MANAGER | " + getName() +
                           " | Pay: " + calculatePay() +
                           " | Team size: " + team.size());
    }
}

import java.util.ArrayList;

public class CompanySystem {

    public static void main(String[] args) {

        System.out.println("=== COMPANY HR SYSTEM ===");

        // إنشاء employees
        Employee e1 = new Employee("Ahmed Ali",    28, 1001, 8000,  Department.IT);
        Employee e2 = new Employee("Sara Hassan",  32, 1002, 7500,  Department.IT);
        Employee e3 = new Employee("Omar Khaled",  25, 1003, 6000,  Department.HR);
        Manager  m1 = new Manager ("Mona Samy",    40, 2001, 15000, Department.IT,    3000);
        Manager  m2 = new Manager ("Tarek Mostafa", 45, 2002, 18000, Department.FINANCE, 5000);

        // بناء الفرق
        m1.addToTeam(e1);
        m1.addToTeam(e2);

        // ArrayList لكل الموظفين
        ArrayList<Person> allPersons = new ArrayList<>();
        allPersons.add(e1); allPersons.add(e2);
        allPersons.add(e3); allPersons.add(m1); allPersons.add(m2);

        // Polymorphism — displayInfo() حسب نوع الـ object
        System.out.println("\n--- All Employees (Polymorphism) ---");
        for (Person p : allPersons) {
            p.displayInfo(); // كل object بينفذ نسخته الخاصة
        }

        // Pay Slips
        System.out.println("\n--- Pay Slips ---");
        e1.printPaySlip();
        m1.printPaySlip();

        // Performance Review مع Exception Handling
        System.out.println("\n--- Performance Reviews ---");
        try {
            e1.performanceReview(4.5);
            e2.performanceReview(6.0); // سيرمي Exception
        } catch (IllegalArgumentException ex) {
            System.out.println("Review Error: " + ex.getMessage());
        } finally {
            System.out.println("Review process completed.");
        }

        // Static field
        System.out.println("\nTotal persons created: " + Person.getPersonCount());

        // Enum usage
        Department myDept = Department.IT;
        System.out.println("Department: " + myDept + " (ordinal: " + myDept.ordinal() + ")");

        // فريق المدير
        m1.displayTeam();
    }
}
