01

مقدمة في البرمجة كائنية التوجه (OOP)

Programming Paradigms • Class • Object • Instance

📖 الشرح

ما هي OOP؟

أسلوب برمجة بيتعامل مع البرنامج كمجموعة Objects. كل object فيه:

  • 📦 Data (Fields): البيانات — اسم الطالب، رقمه، GPA
  • ⚙️ Operations (Methods): العمليات — تعديل GPA، طباعة البيانات

Class vs Object

  • 🏗️ Class: المخطط التصميمي (Blueprint)
  • 🏠 Object: النسخة الحقيقية (Instance)
  • ممكن تعمل كذا Object من نفس الـ Class
Java
public class Student {   // Class = Blueprint
    String name;
    int    id;
    double gpa;
}
Student s1 = new Student(); // Object 1
Student s2 = new Student(); // Object 2
✍️ أسئلة نظرية
  • 1ما المقصود بـ Programming Paradigm؟ وما الفرق بين Procedural وOOP؟
    Programming Paradigm = منهجية تفكير في كتابة البرامج.

    • Procedural: تعليمات متسلسلة (top-down) — البيانات والدوال منفصلة.
    • OOP: بنجمع البيانات والعمليات في Object واحد — أسهل توسعاً وصيانةً.
  • 2ما هو الـ Object؟ اذكر مثالاً من الحياة مع تحديد البيانات والعمليات.
    Object = كائن بيتكون من بيانات + عمليات.

    مثال — سيارة:
    • بيانات: الماركة، الموديل، اللون، سعة الخزان
    • عمليات: تشغيل المحرك، تغيير اللون، عرض المعلومات
  • 3ما الفرق بين الـ Class والـ Object؟ وما معنى "Instance"؟
    • Class: المخطط النظري — بيحدد البيانات والعمليات.
    • Object: النسخة الحقيقية في الذاكرة أثناء التشغيل.
    • Instance: كل Object بنُنشئه هو "instance" — ممكن 100 Student objects من نفس الـ Class.
  • 4لو بتصمم نظام مكتبة، اذكر 4 objects مع بياناتها وعملياتها.
    • Book: title, author, ISBN | getInfo(), updatePrice()
    • Member: name, id, phone | borrowBook(), returnBook()
    • Librarian: name, salary | addBook(), removeBook()
    • Loan: bookId, memberId, dueDate | calculateFine(), extendDate()

02

Classes & Encapsulation

Access Modifiers • private • Getters & Setters • Data Hiding

📖 الشرح

Access Modifiers

  • 🔓 public: يُوصله أي كود من أي مكان
  • 🔒 private: يُوصله بس methods جوه نفس الـ class
  • 🔐 protected: الـ subclasses + نفس الـ package

Encapsulation = Data Hiding

اجعل الـ fields كلها private وفرّ public methods للوصول:

  • 🛡️ Getter: يُرجع قيمة الـ field
  • ✏️ Setter: يُعدل قيمة الـ field
Java — Rectangle مع Encapsulation
public class Rectangle {
    private double length, width;
    public void   setLength(double l) { length = l; }
    public void   setWidth(double w)  { width  = w; }
    public double getLength()         { return length; }
    public double getWidth()          { return width; }
    public double getArea()           { return length * width; }
}
✍️ أسئلة نظرية
  • 1ما الفرق بين public وprivate؟ ولماذا نفضل جعل الـ fields خاصة؟
    • public: يُوصله أي كود من أي مكان.
    • private: لا يُوصله إلا الـ methods داخل نفس الـ class.
    لماذا private؟ لحماية البيانات — نتحكم فيها عبر setters ونتحقق من صحة القيم قبل تخزينها.
  • 2ما المقصود بـ Data Hiding؟ ولماذا هو مهم؟
    Data Hiding = إخفاء البيانات الداخلية عن الكود الخارجي.
    أهميته:
    • يمنع التعديل الخاطئ للبيانات.
    • يُسهّل الصيانة — لو غيرنا طريقة التخزين الداخلية الكود الخارجي لا يتأثر.
    • يضمن نزاهة البيانات (Data Integrity).
  • 3ما الفرق بين الـ Getter والـ Setter؟ أعطِ مثالاً لكل منهما.
    • Getter: يُرجع قيمة الـ field بدون تعديل.
      public double getLength() { return length; }
    • Setter: يقبل قيمة ويُخزنها.
      public void setLength(double l) { length = l; }
  • 4ما هي Instance Fields والـ Instance Methods؟ لماذا تحتاج لـ Object لاستخدامها؟
    Instance Fields: متغيرات تنتمي لكل Object على حدة.
    Instance Methods: دوال بتشتغل على بيانات الـ Object.
    لماذا نحتاج Object؟ لأن الـ instance fields بتتخزن في الذاكرة مع الـ Object — لو ما فيش Object ما فيش ذاكرة مخصصة.

03

Constructors & Static Members & Copy Objects

No-arg • Parameterized • Copy Constructor • Static • Overloading

📖 الشرح

Constructor

  • Method بيتنادى تلقائياً عند إنشاء Object
  • نفس اسم الـ Class، بدون return type
  • لو ما كتبتش constructor، Java بتوفر default constructor

Static Members

  • تنتمي للـ Class نفسه مش لـ Object بعينه
  • تُستخدم باسم الـ Class: ClassName.member
  • Static methods لا تستطيع الوصول للـ instance fields
Java — 3 Constructors + Static
public class Rectangle {
    private double length, width;
    private static int count = 0;

    public Rectangle()                      { length=1; width=1; count++; }
    public Rectangle(double l, double w) { length=l; width=w; count++; }
    public Rectangle(Rectangle r)        { length=r.length; width=r.width; count++; }
    public static int getCount() { return count; }
}
✍️ أسئلة نظرية
  • 1ما هو الـ Constructor؟ اذكر 4 خصائص تميزه.
    Constructor = method خاصة بتُنفَّذ تلقائياً عند إنشاء Object.
    4 خصائص:
    • نفس اسم الـ Class تماماً.
    • لا يوجد له return type — حتى void.
    • لا يُرجع أي قيمة.
    • عادةً public.
  • 2ما هو الـ Default Constructor؟ متى تُوفره Java تلقائياً ومتى لا؟
    Default Constructor = constructor بدون parameters.
    • Java تُوفره: فقط لو ما كتبتش أي constructor.
    • Java لا تُوفره: لو كتبت أي constructor (حتى parameterized).
    القيم الافتراضية: numeric=0، boolean=false، reference=null.
  • 3ما المقصود بـ Method Overloading؟ وما الفرق بينه وبين Method Overriding؟
    • Overloading: نفس الاسم في نفس الـ class لكن بـ parameters مختلفة — compile-time.
    • Overriding: الـ Subclass تُعيد كتابة method من الـ Superclass بنفس الـ signature — runtime.
  • 4ما الفرق بين Reference copy والـ Deep copy؟ ولماذا نستخدم Copy Constructor؟
    • Reference copy: Rectangle r2 = r1; — نفس الـ Object. تعديل r2 يؤثر على r1.
    • Deep copy: Rectangle r2 = new Rectangle(r1); — Object جديد مستقل.
    لماذا Copy Constructor؟ لننشئ نسخة حقيقية مستقلة تماماً.

04

الوراثة (Inheritance)

extends • super • @Override • protected • final

📖 الشرح

Inheritance

  • الـ Subclass ترث fields وmethods من الـ Superclass
  • علاقة "is a": Employee "is a" Person
  • كلمة مفتاحية: extends

Override + super

  • @Override — تُعيد كتابة method من الـ Superclass بنفس الـ signature
  • super(args) — تنادي constructor الـ Superclass — لازم سطر أول
  • super.method() — تنادي نسخة الـ Superclass من method
  • final method = لا يمكن override-ها
Java — Person → Employee
public class Person {
    protected String name;
    protected int age;
    public Person(String n, int a) { name=n; age=a; }
    public void display() { System.out.println(name+" | "+age); }
}
public class Employee extends Person {
    private double salary;
    public Employee(String n, int a, double s) {
        super(n,a); // ← السطر الأول
        salary=s;
    }
    @Override
    public void display() {
        super.display(); // ينادي نسخة Person
        System.out.println("Salary: "+salary);
    }
}
✍️ أسئلة نظرية
  • 1ما المقصود بعلاقة "is a" في الوراثة؟ أعطِ 3 أمثلة.
    علاقة "is a" تعني إن الـ Subclass هي نوع أكثر تخصيصاً من الـ Superclass.
    • Employee "is a" Person
    • Car "is a" Vehicle
    • Dog "is a" Animal
  • 2ما دور الكلمة المفتاحية super في الوراثة؟ اذكر استخدامين.
    super = مرجع للـ Superclass من داخل الـ Subclass.
    • super(args): ينادي Constructor الـ Superclass — لازم السطر الأول.
    • super.method(): ينادي method من الـ Superclass تم override-ها.
  • 3ما الفرق بين private وprotected من حيث الوصول في الوراثة؟
    • private: لا يُرثى — الـ Subclass لا تُوصله مباشرةً، تحتاج public methods.
    • protected: يُرثى — الـ Subclass تُوصله مباشرةً.
  • 4ما تأثير final على الـ method؟ ومتى نستخدمها؟
    final method = لا يمكن للـ Subclass override-ها. أي محاولة = Compiler Error.
    نستخدمها لما نريد ضمان إن سلوك الـ method يبقى ثابتاً في كل الـ subclasses.

Abstract Classes & Interfaces & Polymorphism

abstract • interface • implements • Polymorphism

📖 الشرح

Abstract Class

  • لا يمكن إنشاء Object منها مباشرةً
  • ممكن تحتوي على abstract methods (بدون body) وعادية
  • الـ Subclass لازم تُنفذ كل الـ abstract methods

Interface

  • كل methods فيها abstract | fields = public static final
  • Class ممكن تُنفذ أكتر من interface | كلمة مفتاحية: implements

Polymorphism

نفس الـ reference بتُنفذ سلوك مختلف حسب نوع الـ Object الحقيقي وقت التشغيل

مثال
Animal a = new Dog("Rex");
a.makeSound(); // ينفذ makeSound() من Dog
✍️ أسئلة نظرية
  • 1ما المقصود بـ Abstract Class؟ ولماذا لا يمكن إنشاء Object منها؟
    Abstract Class = class ناقصة التنفيذ، بتمثل الشكل العام لمجموعة classes.
    لا يمكن إنشاء Object منها لأن بعض methods بدون body — البرنامج مش هيعرف ينفذ إيه.
  • 2ما الفرق بين Abstract Class والـ Interface؟ متى تستخدم كل منهما؟
    • Abstract Class: ممكن فيها fields عادية وconstructor وmethods عادية وabstract. تُستخدم في علاقة وراثة حقيقية.
    • Interface: فيها abstract methods بس. تُستخدم لتحديد سلوك مشترك.
    • Class ترث abstract class واحدة بس، لكن ممكن تُنفذ كذا interface.
  • 3لماذا Java تسمح بأكتر من Interface ولا تسمح بالوراثة من أكتر من Class؟
    الوراثة من أكتر من Class ممكن تسبب "Diamond Problem".
    الـ Interfaces ما بيحصلهاش المشكلة دي لأن بتحدد الـ signature بس بدون implementation.
  • 4ما هو Polymorphism؟ وكيف يتحقق في Java؟
    Polymorphism = قدرة الـ reference على الإشارة لأنواع مختلفة من الـ Objects وتنفيذ سلوك مختلف.
    Java بتحدد أنهي method تتنفذ في وقت التشغيل (Dynamic Binding).
